# Робота з Time-Series та JSONB у PostgreSQL 🐘

Це практичне завдання зосереджене на роботі з часовими рядами (time-series) та напівструктурованими даними (JSONB) у базі даних PostgreSQL. Проєкт виконується у середовищі Jupyter Notebook / Google Colab за допомогою локального сервера `pgserver` та `SQLAlchemy`.

## 📊 Джерело даних та спосіб отримання
У проєкті використовуються реальні дані поїздок таксі Нью-Йорка (TLC Trip Record Data):
*   **Датасет:** Yellow Taxi Trip Records (Березень 2024).
*   **Формат:** Parquet.
*   **Отримання:** Файл завантажується автоматично під час запуску скрипта безпосередньо з хмарного сховища AWS (CloudFront) за допомогою модуля `urllib.request.urlretrieve`. Після цього дані фільтруються (очищення аномалій тарифів та дистанції) за допомогою `pandas` і заливаються у PostgreSQL.
*   *Fallback-варіант:* Якщо завантаження недоступне, передбачено генерацію стабільної stub-схеми за допомогою SQL-функції `generate_series`.

## 📈 Time-Series Features
У першій частині роботи реалізовано підготовку даних для часових рядів:
*   **Time Buckets:** Сирі події згруповані у щоденні інтервали за допомогою `DATE_TRUNC('day', ...)`.
*   **Типізація часу:** Продемонстровано використання `TIMESTAMPTZ` з нормалізацією локального часу (`AT TIME ZONE 'America/New_York'`) у стандарт UTC для уникнення проблем із часовими поясами.
*   Створено базові агрегації: кількість поїздок, середня вартість та загальна дистанція для кожної зони таксі.

## 🗂 JSONB-частина та Індексація
Друга частина фокусується на роботі з напівструктурованими документами (event log):
*   **Синтетичні дані:** Згенеровано таблицю `t7_hw_events` на 50 000 рядків із 5 різними типами подій (`page_view`, `click`, `add_to_cart`, `checkout`, `recommendation_shown`), кожна з яких має унікальну вкладену структуру в колонці `payload`.
*   **Запити:** Відпрацьовано оператори входження (`@>` containment), перевірки наявності ключів (`?`, `?|`) та мову запитів JSONPath (`jsonb_path_query`, `jsonb_path_exists`).
*   **Оптимізація та індекси:** Проведено аналіз планів виконання (`EXPLAIN ANALYZE`). Порівняно роботу `Seq Scan` та `Bitmap Index Scan`. Доведено ефективність **GIN-індексу** (`jsonb_path_ops`) для структурних перевірок та **Expression B-tree індексу** для точної текстової рівності (`payload ->> 'device' = 'mobile'`).
*   **Архітектурний вибір:** Проведено порівняння швидкодії JSONB-підходу з класичною нормалізованою SQL-схемою.
